# ADR-0005: Per-agent identity, key strength and rotation

- Status: **Proposed**
- Date: 2026-11-25
- Closes: GS-AUD-06, GS-AUD-07

## Context

All agents share one HMAC key: any key holder can sign as anyone and rewrite `hop`/`taint` (GS-AUD-06). Any 16-byte string is accepted as a key (GS-AUD-07).

## Decision

1. **Key strength.** Keys must be ≥ 32 bytes, supplied as hex or base64 (generated by `keygen`). Raw text keys are refused. Existing 16–31-byte keys load with a deprecation warning in v1.x.
2. **Key hierarchy.** A master key (operator only) derives per-agent keys: `K_agent = HMAC(master, "agent/" + agent_id + "/" + epoch)`. Each agent process receives only its own key.
3. **Verification.** The verifying gate holds the master (or the per-agent keys it is allowed to verify) and checks `sig` with the *sender's* key. A message from A signed with B's key fails.
4. **Rotation.** `epoch` in the envelope; the verifier accepts the current and previous epoch during an overlap window; a revocation list blocks an agent id outright.
5. **Asymmetric option (later).** If an optional dependency is accepted (ADR-0002), Ed25519 per-agent keys replace derivation so verifiers need no secrets.

## Consequences

- A compromised worker agent can no longer impersonate others.
- The verifying gate remains a high-value secret holder until the asymmetric option exists.
